# 明日方舟 PC 客户端 · 鼠标指针资源提取（可复现工程）

本目录是一套**可复现**的提取工程，同时覆盖两条互不相同的指针来源：

| 编号 | 来源 | 性质 | 产出 |
|---|---|---|---|
| **A** | 游戏客户端 `sharedassets0.assets` | 游戏自带的正牌指针，白色箭头，3 档 48/64/96 | 逐像素一致的 PNG + 档位/热点清单 |
| **B** | 本机第三方方案 «PRTS Replica v8 96x» | 用户实际在用的水晶指针，**不在游戏数据内** | 三档尺寸 × 17 角色的可安装指针 |

> **为什么不把两者混为一谈**：A 是游戏资源提取，B 是第三方美术重打包。
> 你（m01001）要的「尖刺水晶指针」属于 **B**，它**不存在于游戏客户端里** —— 详见 `CrystalCursorPack\README.md` §1.1 的穷举证据。

## 二、来源 A：游戏自带指针（白色箭头）

### 2.1 资源位置与格式

| 项目 | 值 |
|---|---|
| 目标文件 | `G:\Hypergryph Launcher\games\Arknights\Arknights_Data\sharedassets0.assets` |
| 贴图 | `cursor_small` path_id=**11** / `cursor_medium` path_id=**7** / `cursor_large` path_id=**13** |
| 配置 | MonoBehaviour `PCCursorRuntimeConfig`（namespace `Torappu.UI`）path_id=**28**，script = `file 1 : path 4099` |
| 尺寸 | 48×48 / 64×64 / 96×96 |
| TextureFormat | **4 = RGBA32（未压缩）**；`m_CompleteImageSize` = 9216 / 16384 / 36864 = `w*h*4` 精确成立；`m_MipCount=1`；`m_IsReadable=True` |
| 热点 | 三档**全部** `(8, 8)` —— 即箭头尖端所在像素，游戏不随档位改变热点 |
| 档位 | 3 档（`CursorTierConfig` 数组，每项 = 贴图 PPtr + 两个 float32 热点） |

### 2.2 依赖

- **Python 3.11.9**
- **UnityPy 1.25.4**（`pip install UnityPy`）
- Pillow（导出 PNG）

### 2.3 运行命令

```powershell
cd G:\ArknightsCursorExtract
$env:PYTHONIOENCODING="utf-8"
python extract_cursors.py
```

产物落在 `extracted\`，与目录中已存的完全一致（可重复性已验收）。

### 2.4 逐像素一致性怎么证明的

`_extract_report.txt` 里记录的是：从 Texture2D 的 `image_data`（原始 payload）按 **bottom-up 行序**还原成像素后算 sha256，与导出的 PNG 解码回像素再按同序算 sha256，**两者逐字节相等**：

| 贴图 | sha256（payload == 导出图） | payload 字节 |
|---|---|---|
| `cursor_small` | `c9b41d746b14aa8e6e6d28df257523e9456f8ffb506d03581c2c03182b044094` | 9216 = 48×48×4 |
| `cursor_medium` | `cd685ccc50e460829da741a04696ddcbaec27e731158d4261b1c7e669d4444ac3` | 16384 = 64×64×4 |
| `cursor_large` | `de0e5c3fd2c3fcc995b7371af620d59c8a5002aa3407d542a467e9700bacbedf` | 36864 = 96×96×4 |

由于 TextureFormat 是**未压缩的 RGBA32**，导出图与原图**不存在任何压缩伪影**。

## 四、`.cur` / `.ani` 二进制格式速查

### `.cur`

```
ICONDIR:   <HHH>            reserved=0, type=2, count      ← 只有 3 个 u16！
  每项:    <BBBBHHII>        w, h, nColors, reserved, hsx, hsy, bytesInRes, imageOffset
                                         ↑ 宽或高为 0 表示 256
payload:   若前 4 字节是 \x89PNG → PNG 压缩
           否则是 BITMAPINFOHEADER: <IiiHH> hdrSize, w, h, planes, bpp
                实际高度 = abs(h) // 2   ← XOR 与 AND 两张位图叠加
                像素 = data[40 : 40+w*h*4]，BGRA，bottom-up
AND 掩码:  ((w+31)//32)*4*h 字节；32bpp 直通 alpha 时可全零
```

### `.ani`

```
RIFF + <size> + ACON
  anih  (36 B): 9 个 u32 — cbSize, nFrames, nSteps, w, h, bpp, planes, dispRate, attrs
  rate  (可选): u32 数组，每帧延时（jiffies）
  LIST  <size> 'fram'          ← 关键：'fram' 是 LIST 的 type 字段
      icon  <size> <完整 .cur 字节流>   ← 载荷是一整份 .cur（因此自带热点！）
      icon  ...
```

> **踩过的坑**：最初把 `fram` 当成 LIST 的**子 chunk** 去找，永远找不到帧。
> 真相是 `fram` 属于 LIST 的 **type 字段**，子块从 LIST 数据起点 **+12 字节**开始
> （8 字节 chunk 头 + 4 字节 type）。
